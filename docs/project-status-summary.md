## 5. 광고 구현과 현재 비활성 정책

처음에는 무료·광고 모델을 검토하고 SDK까지 연결했다. 이후 사용자가 수익화 준비 부담을 줄이고 먼저 출시하기로 하여 **2026-10-13부터 첫 출시 광고·IAP를 제외**했다. 이는 제품 결정이며 사업자 등록 요건에 대한 법적 판단은 아니다.

공통 설정은 `Assets/Resources/AdsSettings.asset` 한 곳이다.

| 항목 | 현재 값 | 의미 |
| --- | --- | --- |
| Enable Ads | false | 앱 코드의 광고·UMP 시작, 광고 안내·표시·빈도 데이터 변경을 비활성 |
| Use Test Ads | true | 광고 재활성화 시 기본 테스트 광고. Editor·Development Build는 테스트 광고 강제 |
| Initialize Ads In Editor | false | 에디터에서 실제 SDK 모형 흐름을 자동 시작하지 않음 |

설정은 화면 컨트롤러 생성 시 읽는다. 실행 중 에셋을 바꿔도 자동 전환되지 않으며 PlayMode 재시작 또는 앱 재빌드가 필요하다. 에셋을 못 찾으면 광고를 사용하지 않는다. 원격 플래그·사용자용 광고 스위치는 아니다.

Google Mobile Ads Unity 11.5.0과 EDM4U 1.2.187은 공식 Git URL의 고정 태그로 설치했다. OpenUPM은 사용하지 않는다. Android 앱 ID와 전면 광고 단위는 연결돼 있고 iOS 운영 ID는 미등록이다. ID의 실제 값·파일 위치는 광고 연동 문서에 보관한다.

광고를 다시 켤 때 사용할 구현은 다음과 같다.

- 일반 완료 판 5회 **및** 실제 플레이 600초를 모두 충족해야 기회가 생긴다. 단순히 5판마다 항상 표시되는 구조가 아니다.
- 최근 24시간 최대 2회. 같은 판 연습·중도 포기·일시정지 시간은 제외한다.
- 결과 저장 후 광고가 준비된 경우에만 안내와 `광고 후 새 판` 버튼을 표시한다. 플레이 중에는 끼워 넣지 않는다.
- 광고가 없거나 실패하면 다음 판으로 진행하며 놓친 광고를 나중에 보충하지 않는다.
- UMP가 요청을 허용한 경우 광고를 요청한다. 고참여 광고는 콘솔에서 껐다고 사용자가 확인했다.
- 콘솔 동의 메시지, iOS 운영 ID와 양쪽 실제 동의·복귀 검증은 후속 광고 도입 때 다시 준비한다.

**광고 플래그를 끄는 것은 네이티브 SDK를 빌드에서 제거하는 것과 다르다.** 패키지와 의존성이 남아 있으므로 최종 산출물의 권한·초기화·외부 전송 확인 후 개인정보 설명을 확정한다.

## 6. 후속 수익 모델 후보

사용자는 반복적인 긴 전면 광고와 닫기 어려운 경험을 피하고 싶어 한다. 기본 솔로를 편하게 유지하면서 가치가 있는 후속 기능에 수익화를 붙이는 방향이다.

- 제한적인 솔로 광고와 결과 화면의 사전 안내.
- 광고 제거 구매와 개발 응원·사용료 성격의 설명.
- 도전·경쟁 모드의 추가 도전 기회 또는 입장권. 시도 횟수가 경쟁 공정성에 주는 영향은 별도 검토.
- 자신의 판이나 고득점 플레이를 분석하고 접근법을 제시하는 트레이너·분석 팩.
- 멀티·랭킹·스킨·구독 등은 수요와 제공할 가치가 확인된 뒤 판단.

모두 후속 후보이며 상품 가격·보상량·경제 시스템·출시 시점은 확정하지 않았다. 첫 출시를 위해 구현하지 않는다.

개발 메뉴 `Tools → Squapple → Build Android Development`는 현재 프로필과 별개로 `com.squapple.development`의 Development APK를 만든다. 출력은 `Builds/Android/Squapple-development.apk`다. 제출용 메뉴로 사용하지 않는다. 임시 식별자 복구 시 자동 생성 여부까지 보존하는지는 후속 정리 항목이다.

### API 36을 선택했는데 파일에 30이 찍힌 원인

사용자 제보 후 **현재 열린 Unity 6000.6.4f1 설정 화면의 변환 오류를 직접 확인**했다. 메뉴 목록은 API 32부터인데 선택 위치를 저장값으로 바꾸는 최소 기준이 26으로 잡혀 있었다. 실제 화면 객체의 변환 결과는 다음과 같다.

| 화면 선택 | 실제 저장 변환 |
| --- | --- |
| API 35 | 29 |
| API 36 | 30 |
| API 37 | 31 |

따라서 30이 36을 나타내는 정상적인 내부 코드인 것은 아니다. 이전 API 조회에서도 실제 값은 API 30이었다. 사용자가 잘못 선택했다고 판단하면 안 된다.

드롭다운을 우회해 `PlayerSettings.Android.targetSdkVersion = AndroidSdkVersions.AndroidApiLevel36`을 적용하고 저장했다. 적용 직후 Unity API와 파일에서 모두 **36**을 확인했다. 이후 파일 재확인에서도 36이었다. 후속 Pipeline 연결이 없어 에디터 재시작 후 유지 여부와 실제 APK/AAB target SDK는 아직 확인하지 못했다. 다른 설치에서의 재현이나 공식 수정 버전도 확인하지 않았다.

이 문제가 해소되기 전에는 메뉴 문구만으로 판단하지 말고 저장값과 최종 빌드 값을 확인한다. 상세 재현 근거와 적용 코드는 빌드 점검 문서에 있다.

## 9. 키스토어 관리 결정

- 빌드 장소가 많지 않아 **현재는 사용자가 별도 관리**한다.
- 프로젝트 밖의 고정 위치에 두고 별도 복구용 사본을 유지한다.
- 파일·비밀번호는 Git에 넣지 않는다. `.jks`·`.keystore`와 해당 meta 제외 규칙은 직전 커밋에 포함했다.
- 자동 주입 스크립트나 외부 보관소 연동은 현재 도입하지 않는다.
- Unity Publishing Settings에서 파일·별칭을 연결하고 필요한 비밀번호를 입력한다.
- Play App Signing과 별도 업로드 키 사용을 권장했으나, 실제 키 생성·백업·서명 연결 완료는 아직 확인되지 않았다.

## 10. 홈페이지·앱 개인정보처리방침

- 도메인과 홈페이지는 `https://prolly.works`다. 사이트 편집·배포는 사용자가 별도로 담당한다.
- 공개 연락처를 앱에도 사용한다: 일반 문의 `hello@prolly.works`, 앱 지원 `support@prolly.works`, 개인정보 문의 `privacy@prolly.works`.
- 웹사이트 방침은 사이트 방문·호스팅·분석·브라우저 저장을, 앱 방침은 로컬 기록·SDK·데이터 전송·삭제·지원 문의를 설명한다. 현재 사이트 구성에는 앱 전용 페이지를 추가하는 방향을 제안했다.
- 소개·지원·앱 방침의 한국어·영어 문구와 경로 제안은 전달 문서에 있다. 제안 경로를 이미 게시된 URL로 취급하지 않는다.
- 2026-10-13 사이트 확인 당시 분석 스크립트와 ‘방문 분석 없음’ 설명이 일치하지 않았다. 수정 요청 사항으로 전달했으며 이번 요약에서 사이트 변경 여부를 다시 확인하지 않았다.
- 광고가 없다는 이유만으로 데이터 수집이 전혀 없다고 쓰지 않는다. Unity Engine Diagnostics 설정과 포함 SDK를 실제 산출물 기준으로 확인해야 한다.

## 11. 남은 작업 순서

1. **빌드 설정 마무리**: Android·iOS 식별자와 버전 규칙 확정, 대상 API 36 유지 확인, 개발 APK와 제출 AAB 용도 구분.
2. **광고 없는 산출물 점검**: 네이티브 SDK·병합 Manifest·권한·진단 설정·외부 전송, 16 KB 페이지 호환성 확인. 최신 APK 생성.
3. **Android 실기기 회귀 검증**: 오프라인 플레이, 기록·설정 유지, 중단·복귀·강제 종료, 업데이트 설치, 광고 미노출 확인.
4. **서명·스토어 자료**: 업로드 키 생성·백업·Unity 연결, 아이콘·스크린샷·소개·지원·앱 방침 준비. 실제 데이터 처리와 스토어 답변 일치.
5. **Play 내부 테스트**: AAB 생성·검증·업로드, 실제 배포 설치·업데이트 확인. 계정별 추가 테스트 요건은 콘솔에서 확인.
6. **iOS 경로 확보**: Mac mini M1의 Unity·Xcode·서명 준비, iPhone·iPad에서 Safe Area·플레이·저장·복귀 확인, TestFlight 경로 확보.
7. **출시·첫 수정 업데이트**: 심사·공개 후 사용자 피드백을 반영. 이후에 광고·도전·경쟁·트레이너 등의 가치를 검토.

기본 플레이는 구현됐다는 이유만으로 실기기·정책·배포 검증까지 완료 처리하지 않는다. 새로운 수익 모델이나 전체 시안 적용을 현재 출시 준비의 선행 조건으로 늘리지 않는다.
