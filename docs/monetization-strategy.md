# 사각사과 · Squapple 수익화와 제품 확장 검토

- 작성·공식 자료 확인: 2026-10-10
- 상태: 사용자 방향을 반영한 검토안. 가격·노출 수치·유료 상품·후속 모드의 구현은 아직 확정하지 않았다.
- 연결: [모바일 출시 체크리스트](mobile-release-checklist.md), [현재 로컬 기록](local-progress.md)
- 목표: 기본 솔로를 편하게 반복할 수 있게 유지하고, 더 깊이 도전하고 배우려는 이용자에게 실제 가치가 있는 상품을 제공한다.

## 1. 사용자 방향과 이번 추천의 구분

사용자는 갑자기 나오는 전면 광고 때문에 앱을 종료하는 경험을 말했다. 기본 혼자 플레이에서는 광고를 제한하고 미리 알리는 방향을 선호하며, 향후 멀티·도전·경쟁·트레이너에 수익 모델을 붙이는 안을 검토해 달라고 요청했다. 2026-10-10 사용자는 개발자 계정 등록 확인 중이며 AdMob 등록을 마쳤다고 보고했다. 플랫폼별 앱 등록·광고 단위·ID는 아직 확인하지 않았다. IAP 준비 부담으로 당분간 광고만 운영하는 방향을 검토 중이며, 결제는 광고 연동의 선행 조건으로 두지 않는다.

이번 추천은 다음과 같다. 아래 수치와 상품 구성은 업계의 정답이나 사용자 확정값이 아닌 실험안이다.

1. 기본 솔로는 무료·오프라인·횟수 제한 없음. 제한된 광고와 광고 제거 1회 결제를 우선 검토한다.
2. 다음 제품 실험은 같은 판 복기와 비동기 도전. 실시간 멀티보다 적은 운영 범위에서 반복 사용 가치를 확인한다.
3. 트레이너는 유력한 후속 유료 기능 후보. 먼저 재현 가능한 기록과 유용한 분석을 만들고 지불 의사를 확인한다.
4. 경쟁의 공식 기록 기회를 광고·결제로 늘리는 방식은 추천하지 않는다. 추가 도전권은 비랭킹 콘텐츠에서 먼저 검토한다.

이 문서는 광고 SDK나 미래 모드가 구현됐다는 뜻이 아니다. 현재 7단계의 개발 순서를 유지한다.

## 2. 기본 솔로 광고 경험

### 노출 규칙의 출발점

| 항목 | 실험 기본안 |
| --- | --- |
| 첫 노출 자격 | 일반 판 5회 완료와 실제 플레이 10분을 모두 충족 |
| 다음 노출 자격 | 직전 광고 이후 다시 5회 완료와 실제 플레이 10분을 모두 충족 |
| 하루 상한 | 기기 기준 하루 최대 2회. 출시 수익을 예상하는 값이 아닌 보수적 실험값 |
| 시간 계산 | 일반 판의 실제 진행 시간. 메뉴·일시정지·백그라운드·광고 시간 제외 |
| 표시 위치 | 결과 저장과 확인을 마친 뒤 새 일반 판으로 전환할 때 |
| 제외 | 앱 실행·복귀·종료, 플레이 중, 설정, 같은 판 연습 |
| 실패·광고 없음 | 기다림 없이 새 판 시작. 놓친 광고를 쌓아두거나 연속으로 보충하지 않음 |
| 재실행 | 노출 이력과 간격을 유지. 재실행 직후에 누적 광고를 강제 표시하지 않음 |

여기서 사용자가 말한 넓은 의미의 ‘혼자 연습’은 기본 솔로 경험을 뜻한다. 현재 UI의 ‘같은 판 연습’은 별도 기능이며 기존 추천대로 광고 대상에서 제외한다.

이 안에서는 짧게 몇 판만 즐기는 이용자는 광고를 보지 않을 수 있다. 광고 수익이 적어지는 선택을 받아들이고, 반복 이용과 불만을 함께 본다. 2026-10-11 첫 구현은 최근 24시간 최대 2회를 기준으로 하며 완료 판과 실제 노출 시점에 저장한다. 자정 직후 제한이 초기화되지 않고 기기 시간을 뒤로 바꿔도 제한이 풀리지 않는다. 구현·검증과 남은 실기기 항목은 [광고 연동 문서](ads-integration.md)에 기록한다. 이를 온라인 부정행위 방지 시스템으로 확대하지 않는다.

### OTT처럼 미리 알려주는 방법

예고는 놀람을 줄일 수 있지만, 기다리기 싫다는 문제까지 해결하지는 않는다. 예고가 붙었다는 이유로 빈도를 높이지 않는다.

- 노출 자격을 충족하고 광고가 준비된 결과 화면에서 작은 사과 아이콘과 `다음 판 시작 전에 광고가 표시돼요`를 보여준다.
- 결과 화면에는 원래대로 새 판·같은 판 연습·홈 선택지를 둔다. 광고가 예정된 경우 새 판 버튼에도 `광고 후 새 판`으로 표시해 결과 안내와 연결한다. 머무르거나 홈으로 가는 행동만으로 광고를 시작하지 않는다.
- 플레이 중 카운트다운이나 별도의 강제 대기 화면을 추가하지 않는다. 광고 전 안내 때문에 또 기다리게 만들지 않는다.
- `5초만 기다리세요`처럼 실제 소재가 보장하지 않는 길이를 약속하지 않는다.
- 해당 결과 화면에서 안내할 수 없었던 광고를 늦은 로딩 완료만으로 갑자기 띄우지 않는다. 다음 판이 시작되면 그 전환 기회는 끝난다.
- 광고가 열리기 전에 앱이 중단되면 재개 직후 자동 표시하지 않는다. 결과 화면으로 돌아와 사용자가 다시 진행하도록 한다.

Google은 자연스러운 콘텐츠 전환과 사전 로딩을 권장하며, 특히 일반적인 다음 버튼을 누른 뒤 광고가 나타나 놀라는 상황을 줄이도록 휴식 화면·다음 버튼보다 앞선 표시를 권한다. 위 안은 결과를 먼저 확인하고 광고를 명시한 버튼으로 진행하게 하는 프로젝트의 실험안이다. 공식 권장 배치와 차이가 있으므로 연동 시 오인·연속 탭·우발 클릭을 점검하고 최종 배치를 정한다. 안내 UI의 만족도 향상이나 심사 통과가 입증됐다는 뜻은 아니다. [공식 전면 광고 구현 안내](https://support.google.com/admob/answer/6201350)

### 광고 길이와 닫기 경험

AdMob의 ‘고참여 광고’는 기본 활성화다. 적용 대상 전면 광고에서 끄면 건너뛰기 대기는 최대 5초, 종료는 최대 2단계로 안내돼 있다. 켜면 각각 최대 12초·3단계다. 표준 광고 단위에 적용되며 파트너 입찰 광고 단위에는 적용되지 않는다. 초기 운영에서는 비활성화를 추천한다. [고참여 광고 설정](https://support.google.com/admob/answer/15525707)

모든 소재의 닫기 버튼이나 전체 체류 시간을 앱에서 직접 통제할 수는 없다. 일부 외부 입찰 전면 광고에는 최대 30초의 닫기 대기가 있을 수 있다. 한 광고망으로 시작하고, 실제 광고 경험을 검토한 뒤 광고원 확대를 판단한다. 테스트 광고 검증만으로 실제 소재 품질까지 확인한 것으로 기록하지 않는다. [AdMob 전면 광고 가이드](https://support.google.com/admob/answer/6066980)

## 4. 도전권·입장 재화는 어디에 붙일까

### 비랭킹 도전에서 먼저 실험

한정된 무료 체험 후 `광고 보고 추가 도전 3회` 또는 문제 묶음 구매 같은 모델은 후보가 될 수 있다. 3회는 예시이며 아직 보상값이 아니다. 무료 기본 솔로는 계속 열어두고, 추가 상품에는 선별된 문제·새 목표·해설처럼 구분되는 가치가 있어야 한다.

초기에는 코인→보석→입장권 같은 교환 단계를 만들지 않는다. 필요하면 입장권 하나 또는 문제 묶음 직접 구매로 시작한다. 광고를 안 보거나 준비된 광고가 없어도 기본 솔로는 이용할 수 있어야 한다.

광고 보상은 보기 전에 수량·사용처를 명확히 안내하고 이용자가 직접 선택하게 해야 한다. 완료 조건 충족 시 약속한 보상을 지급하며, 일반 이용을 방해하는 거부 처리를 만들지 않는다. AdMob은 현금 보상과 양도 가능한 보상을 제한한다. 여기서는 앱 안에서 본인만 쓰는 비환전 도전권·분석권을 검토한다. [보상형 광고 정책](https://support.google.com/admob/answer/7313578)

‘개발 응원’ 표현은 광고 제거 구매 설명에 사용할 수 있지만, 보상형 광고 선택 버튼에는 `광고 보고 분석 1회 받기`처럼 보상 자체를 설명한다. Google은 보상 설명 외에 사업 지원 등을 이유로 시청을 유도하는 문구를 금지한다. 같은 정책의 구현 요건을 따른다.

### 경쟁의 기회는 별도로 설계

동일 보드에서 최고점을 채택하는 경쟁이라면 시도 횟수도 결과를 바꾸는 자원이다. 점수 배율이나 힌트를 팔지 않아도 추가 시도를 판매하면 경쟁 우위가 생길 수 있다.

추천 예시는 `공식 시도는 모두 동일한 N회, 추가 플레이는 연습 기록`이다. N은 모드 설계 때 결정한다. 공식 시도 중에는 시간 연장·이어하기·실시간 코칭을 제공하지 않는다. 경쟁 매칭에 들어간 뒤 광고로 상대방을 기다리게 하지 않는다.

공식 도전이 진행 중인 동일 보드의 랭커 리플레이와 상세 풀이를 판매·공개하면 후발 참가자가 유리해질 수 있다. 공통 보드 대회에서는 해당 이벤트 마감 후 공개하는 안을 기본으로 검토한다. 연습·다른 계정·공유를 통한 사전 노출까지 완벽히 막을 수 있다고 가정하지 않는다.

실시간 멀티는 참가자 수가 적을 때 입장 제한이 매칭 대기와 이탈을 늘릴 수 있다는 제품 가설도 확인해야 한다. 초기 핵심 경쟁 참여는 넓게 열고, 방 개설 편의·꾸미기·경기 후 분석을 먼저 유료 후보로 둔다.

## 5. 트레이너의 가치와 최소 실험

트레이너가 제공할 가치는 ‘점수가 낮다’는 평가보다 다음 판에서 적용할 수 있는 구체적인 연습 과제다. 수요는 아직 검증되지 않았으며, 고득점 플레이가 존재한다는 사실만으로 유료 분석 수요가 있다고 보지는 않는다.

### 현재 코드에서 가능한 출발점

2026-10-10 파일 확인 결과:

- [LocalProgress](../Assets/Scripts/Presentation/LocalProgress.cs)는 마지막 완료 판의 원본 숫자·규칙·점수·종료 이유를 저장한다. 행동 순서와 시각은 저장하지 않으므로 현재 저장만으로 지난 플레이를 재생할 수 없다.
- [GameSession](../Assets/Scripts/Gameplay/GameSession.cs)은 선택 확정 때 [SelectionResolved](../Assets/Scripts/Gameplay/SelectionResolved.cs)를 발행한다. 여기에는 사각형·판정 결과·일시정지를 제외한 경과 시간이 있어 후속 기록의 출발점이 된다.
- 지금은 기록 형식을 확대하지 않는다. 트레이너 실험을 시작할 때 원본 보드·규칙 버전·선택 순서와 시각·종료 시각/이유를 기록하고 최종 보드·점수 재현부터 검증한다. 원시 손가락 이동 경로는 첫 분석에 필요하지 않다.

### 단계별 가치 검증

| 단계 | 작은 결과물 | 다음 단계로 갈 근거 |
| --- | --- | --- |
| 1. 복기 | 방금 한 판을 앞뒤로 넘기며 실제 선택과 시간을 확인 | 기록 재생이 실제 결과와 일치하고 이용자가 다시 열어봄 |
| 2. 기초 분석 | 오답 선택, 선택 사이 시간, 그 시점의 가능한 합 10 영역 | 설명이 이해되고 유저가 다음 행동을 정할 수 있음 |
| 3. 대안 비교 | 특정 시점에서 가능한 다른 선택과 후속 전개를 비교 | 제시한 대안이 규칙상 유효하고 비교 근거가 재현됨 |
| 4. 훈련 과제 | 유사 패턴의 새 판에서 탐색·선택을 반복 | 같은 판 암기 외에 새로운 비슷한 판에서도 도움이 됨 |
| 5. 고수 비교 | 허락받은 같은 보드의 플레이와 분기 비교 | 공개·활용 동의, 기록 검증, 해설 품질과 학습 수요 확보 |

첫 실험 화면은 `복기 타임라인 + 살펴볼 장면 하나 + 다음 연습 하나` 정도로 제한한다. 예를 들어 오래 멈춘 구간의 가능한 선택을 보여줄 수 있지만, 멈춘 이유를 ‘집중력이 낮다’고 추정하지 않는다.

가능한 수를 많이 남기는 선택이 반드시 최종 최고점을 만드는 것은 아니다. 제한된 탐색은 ‘찾은 대안’, 랭커의 기록은 ‘이 플레이어의 경로’로 표시한다. 완전 탐색으로 증명하지 않은 ‘최적해·놓친 확정 점수·이 수 때문에 패배’는 단정하지 않는다.

LLM을 반드시 붙일 필요는 없다. 보드 판정·실제 행동·검증된 대안을 먼저 만들고 설명 문구를 붙인다. 자연어 설명 생성이 나중에 필요해져도 존재하지 않는 수나 점수를 만들어내지 않도록 게임 로직으로 검증한다.

### 유료화 후보

- 자신의 최근 판에 대한 기본 복기는 무료로 체험하게 한다.
- 기기 안에서 완결되는 상세 분석 도구는 1회 구매 후보로 둔다.
- 사람이 선별·해설한 훈련 문제는 주제별 팩으로 판매할 수 있다.
- 서버 분석과 새로운 훈련이 계속 제공되고 반복 수요가 확인된 경우에만 구독을 검토한다. 무제한 서버 분석을 원가 확인 없이 약속하지 않는다.
- 보상형 광고로 분석 1회를 제공하는 체험은 후속 후보다. 광고 수익이 분석 비용을 감당하는지는 실제 데이터로 확인한다.

Apple은 자동 갱신 구독에 지속적인 가치를 요구한다. 정적인 도구 한 개만 있는 단계에서는 1회 결제가 제품 설명도 단순하다. [Apple 구독 지침 3.1.2](https://developer.apple.com/app-store/review/guidelines/#subscriptions)

## 6. 광고 제거 상품의 약속

광고 제거는 한 번 구매하는 비소모성 상품을 우선 검토한다. Google Play도 광고 없는 버전을 비소모성 상품의 예로 든다. [일회성 상품 안내](https://developer.android.com/google/play/billing/one-time-products)

구매 설명에서는 `한 번 구매하면 광고 없이 플레이할 수 있어요. 구매는 개발과 업데이트에 도움이 됩니다`처럼 혜택을 먼저 알린다. 반복 구매 팝업, 실패 직후 구매 압박, 응원을 강요하는 표현은 사용하지 않는다.

판매 전에 제거 범위를 정해야 한다. 아직 보상형 광고가 없으므로 현재 상품 후보는 ‘자동 전면 광고 제거’다. 향후 보상형 광고를 추가할 가능성을 남길 경우 판매 화면에 자동 광고 제거 범위를 명확히 쓰고, ‘모든 광고 영구 제거’라고 판매한 권리를 나중에 축소하지 않는다. 모든 광고 제거로 판매한다면 후속 보상은 광고 없이 받을 방법까지 설계해야 한다.

‘광고 제거’가 향후 유료 훈련 팩·온라인 서비스까지 모두 포함한다는 의미로 쓰이지 않게 한다. 가격은 아직 정하지 않는다. 구매 복원·환불 후 권한·오프라인 사용 기준을 상품 구현과 함께 검증한다.

재화를 판매하게 되면 무료 배포분과 구매분의 소멸 규칙을 섞지 않는다. Apple은 IAP로 구매한 재화의 만료를 허용하지 않으며 복원 가능한 구매의 복원 수단을 요구한다. 양쪽 플랫폼의 스토어 결제를 기본 구현 경로로 검토한다. [Apple IAP 지침 3.1.1](https://developer.apple.com/app-store/review/guidelines/#in-app-purchase)

## 7. 실험 순서와 관측

| 순서 | 진행할 일 | 확인 기준 |
| --- | --- | --- |
| 현재 7단계 | AdMob 테스트 광고·UMP, 제한된 노출·예고·실패 시 진행 | 광고 없음·중단·닫기·늦은 응답에도 다음 판과 기록이 정상 |
| 첫 출시 전 상품 결정 | 광고 제거 1회 결제를 함께 낼지 결정 | 판매 범위·가격·복원·플랫폼 검증 부담을 정함 |
| 첫 출시 및 수정 | 기본 반복 플레이와 광고 불편 확인 | 광고 있는 전환/없는 전환의 다음 판 진입, 재방문, 직접 피드백 |
| 다음 작은 제품 실험 | 최근 판 복기와 기초 분석 | 이해도·다시 사용한 이유·다음 판에서 적용한 행동 확인 |
| 도전 실험 | 비동기 친구 도전 또는 선별 문제 | 순위·참여 기회·추가 콘텐츠의 가치가 분명함 |
| 검증된 후보 유료화 | 훈련 도구 또는 콘텐츠 팩 하나 | 샘플 사용 후 지불 의사와 실제 구매/반복 사용을 확인 |
| 후속 서비스 | 서버 분석·랭킹·실시간 멀티 중 수요가 있는 것 | 운영 비용·공정성·참가자 규모를 충족 |

광고 관측에서는 안내 노출, 광고 실제 열림/닫힘, 다음 판 시작, 광고 오류를 구분한다. 광고 클릭률을 높이는 UI를 목표로 하지 않는다. 광고 앱으로 이동하거나 앱이 종료된 경우를 모두 광고 불쾌감에 의한 이탈이라고 단정하지 않는다.

초기에는 수익보다 이용자가 광고 때문에 그만두는지와 설명이 기대에 맞는지를 먼저 확인한다. 표본이 작으면 5판·10분·2회가 적정하다고 통계적으로 결론 내리지 않는다. 먼저 수 명의 실제 반응을 받고, 충분한 사용량이 생기면 광고 없는 비교 조건과 함께 한 요소씩 바꾼다. 새 관측 항목은 체크리스트 8단계에서 수집 목적과 개인정보 설명에 함께 반영한다.

트레이너는 사용 전후 동일 보드 점수만 비교하지 않는다. 익숙해진 효과를 구분할 수 있도록 보지 않은 비슷한 난도의 판, 조언 적용 여부, 반복 사용 이유도 살핀다. 구매 전 설문만으로 수익성이 검증됐다고 보지 않는다.

## 8. 지금 결정한 범위와 남은 결정

- **방향 반영:** 기본 솔로의 부담을 낮추고 광고를 예고하는 경험, 후속 도전·경쟁·훈련의 가치에 기반한 BM 검토.
- **실험 제안:** 5판·10분·하루 2회, 결과 화면 예고, 고참여 광고 비활성화. 실제 연동·체감 확인 후 조정한다.
- **아직 미정:** 광고 제거의 첫 출시 포함·가격·범위, 미래 모드의 규칙과 무료/유료 경계, 트레이너 상품 구성.
- **바로 다음 작업:** 사용자의 AdMob 준비와 병행해 현재 7단계의 테스트 광고 연동을 진행한다. 실제 계정의 앱 ID·광고 단위·동의 메시지는 준비 상태를 확인해 연결한다.
- **확대하지 않을 현재 구현:** 미래 도전권 지갑·온라인 계정·경제 시스템·LLM 호출은 해당 가치 실험을 시작할 때 구현한다. 기존 세션·선택 이벤트 경계를 활용하며 범용 수익화 프레임워크를 미리 만들지 않는다.
