# AdMob 연동과 검증

- 작업일: 2026-10-11
- 범위: 7단계 전면 광고·동의 처리. IAP는 보류.
- 운영 방향: [수익화 검토](monetization-strategy.md)

## 설정

| 항목 | 값 |
| --- | --- |
| Unity 패키지 | Google Mobile Ads for Unity 11.5.0, 공식 저장소의 Git 패키지 |
| 의존성 관리자 | External Dependency Manager 1.2.187 |
| Android 네이티브 광고 SDK | 25.4.0, 표준 SDK 사용 |
| Android 앱 ID | `ca-app-pub-8213531068089130~2242373070` |
| Android 운영 전면 광고 단위 | `ca-app-pub-8213531068089130/4983077327` |
| iOS | 운영 ID 미등록. 개발용 Google 샘플 앱 ID만 사용하며 운영 광고 요청은 비활성 |

앱 ID는 `Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings.asset`에, 광고 단위 ID는 `AdMobInterstitial.cs`에 보관한다. 앱 ID와 광고 단위 ID는 서로 대체하지 않는다.

`Packages/manifest.json`에서 두 패키지를 버전 태그가 고정된 Git URL로 등록한다. AdMob 패키지의 EDM4U 의존성은 버전 번호로 선언돼 있으므로 프로젝트에서 EDM4U Git URL도 직접 지정한다. OpenUPM scoped registry는 사용하지 않는다.

```text
https://github.com/googleads/googleads-mobile-unity.git?path=packages/com.google.ads.mobile#v11.5.0
https://github.com/googlesamples/unity-jar-resolver.git?path=upm#v1.2.187
```

`PlayPrototype`의 `useTestAds` 기본값은 true다. 이 값이 true이거나 Unity Editor·Development Build이면 Google의 플랫폼별 테스트 광고 단위만 요청한다. Android 운영 광고를 활성화하려면 실제 계정·앱·동의 설정과 실기기 검증을 마친 뒤 이 값을 false로 바꾸고 비개발 빌드를 만든다. iOS는 운영용 앱 ID와 광고 단위 ID가 모두 필요하다.

에디터에서는 기본적으로 광고 SDK를 자동 초기화하지 않는다. 자동 테스트에는 통제 가능한 광고 대역을 사용한다. SDK의 에디터 모형 광고를 확인할 때만 `initializeAdsInEditor`를 켠다. 에디터 모형은 네이티브 광고 표시나 실제 동의 메시지의 검증을 대신하지 않는다. [테스트 광고](https://developers.google.com/admob/unity/test-ads)

## 게임 흐름

- 완료한 일반 판 5회와 실제 플레이 600초를 모두 채워야 광고 기회가 생긴다. 같은 판 연습·중도 포기·일시정지 시간은 포함하지 않는다.
- 광고 노출은 **최근 24시간에 최대 2회**다. UTC 시각으로 저장해 자정 직후 제한이 즉시 초기화되는 상황을 피한다. 기존 ‘하루 최대 2회’ 제안의 구현 기준이다.
- 빈도 데이터는 별도 PlayerPrefs 키 `Squapple.Ads`에 저장한다. 앱 재실행에도 유지하며, 손상되거나 더 새로운 저장 형식이면 광고를 생략하고 해당 데이터를 덮어쓰지 않는다.
- 결과 저장 후 광고가 준비돼 있던 경우에만 결과 화면에 예고와 `광고 후 새 판` 버튼을 표시한다. 결과 이후에 로딩이 끝나도 그 화면에는 광고를 새로 끼워 넣지 않는다.
- 표시 조건을 충족한 새 판 전환에서 광고가 없거나 만료·실패하면 바로 진행하고 다음 간격을 새로 센다. 놓친 광고를 보충하지 않는다.
- 실제 광고 화면이 열리면 노출 이력을 저장한다. 표시 실패는 일일 노출 횟수를 소비하지 않는다.
- 광고를 닫은 뒤 포커스와 백그라운드 상태가 모두 복구된 경우에만 새 판을 시작한다. 화면 비활성화·파괴 뒤 도착한 콜백으로 판을 시작하지 않는다.
- 광고 로딩 실패 때 즉시 반복 요청하지 않는다. 최소 30초 뒤 홈·판 시작·결과 같은 다음 준비 기회에서 다시 시도한다. 불러온 광고는 1시간이 지나면 사용하지 않는다.

## 동의와 개인정보 선택

실제 앱에서는 Unity 콜백 처리기를 먼저 만들고 UMP 동의 정보를 갱신해 필요한 양식을 표시한다. 콜백 처리기 생성은 광고 SDK 초기화와 별개다. `CanRequestAds()`가 허용할 때만 광고 SDK를 초기화·요청한다. 갱신 실패 때도 UMP가 이전 동의로 요청을 허용하는지 확인하며, 그렇지 않으면 광고를 생략한다. 자체 저장한 동의 플래그로 판단하지 않는다.

동의 양식이 필요한 상태에서 게임이 이미 진행 중이면 일시정지한다. 양식을 닫아도 수동으로 재개한다. UMP가 개인정보 선택 경로를 요구하면 설정에 `광고 개인정보 설정` 버튼을 표시한다. 변경 전에 기존 광고와 진행 중인 로딩을 무효화하고 변경 후 허용 여부를 다시 확인한다. [UMP 공식 안내](https://developers.google.com/admob/unity/privacy)

### 콘솔 준비 상태와 다음 순서

2026-10-11 사용자 확인 기준:

- Android 전면 광고 단위의 **고참여 광고는 사용 중지**했다. 실제 광고 소재의 닫기 경험은 실기기에서 별도로 확인한다.
- **동의 메시지는 아직 준비하지 않았다.** UMP 코드 연결과 콘솔 메시지 게시는 별도 작업이다.
- **공개 개인정보처리방침 URL은 없다.** 게시용 방침에 사용할 개발자 표시 이름·문의 이메일도 아직 전달받지 않았다.
- 광고 단위의 콘솔 게재빈도 제한은 미확인이다. 앱 내부의 최근 24시간 2회 제한은 구현돼 있다.
- 계정·앱 검토, 스토어 연결 등 운영 광고 제공 준비 상태는 별도 확인한다. 테스트 광고 성공을 운영 광고 승인으로 해석하지 않는다.

유럽 동의 메시지는 아래 순서로 준비한다. 이는 EEA·영국·스위스용 메시지이며, 그 밖의 출시 지역에 필요한 설정은 출시 국가를 확정할 때 별도로 확인한다.

1. 개발자 표시 이름·문의 이메일을 확정하고 실제 앱의 데이터 처리에 맞는 개인정보처리방침을 작성해 공개 URL을 준비한다.
2. AdMob의 **개인정보 보호 및 메시지 → 유럽 규정 → 만들기**에서 `Squapple / Android` 앱을 선택한다.
3. 해외 출시 계획에 맞춰 기본 언어는 영어, 추가 언어는 한국어로 설정한다. 이는 프로젝트 제안이며 게시 전에 두 언어의 미리보기를 확인한다.
4. 사용자가 첫 화면에서 거절할 수 있도록 **동의하지 않음**을 사용 설정하는 방향으로 준비한다. 타겟팅은 우선 **GDPR이 적용되는 국가**를 선택한다.
5. 메시지 이름은 구분하기 쉽게 `Squapple Android - European consent`로 지정하고 개인정보처리방침 URL을 연결한다. URL 준비 전에는 **임시 저장**한다.
6. 언어·앱·정책 링크·사용자 선택을 검토한 뒤 게시한다. [AdMob 공식 메시지 작성 안내](https://support.google.com/admob/answer/10113207?hl=ko)
7. 테스트 기기에서 동의·거부·설정 변경·오프라인 동작을 확인한다. 한국에서 유럽 메시지가 자동으로 나오지 않는 것만으로 실패로 판단하지 않는다. EEA 조건을 강제로 확인하려면 UMP의 테스트 기기·디버그 지역 설정이 필요하며, 현재 앱에는 이를 켜는 별도 설정을 추가하지 않았다. [UMP 테스트 안내](https://developers.google.com/admob/unity/privacy#testing)

## 검증 기록

- 공식 Git 패키지 두 개가 정상 설치되고 `packages-lock.json`에 실제 커밋 해시가 기록됐다. OpenUPM registry 제거를 확인했다.
- Unity CLI/Pipeline 컴파일 오류 0개, EditMode **94/94**, PlayMode **23/23** 통과. 빈도 저장·최근 24시간 제한, 같은 판 연습 제외, 늦은 로딩·만료, 결과 선저장, 중복 탭·콜백, 백그라운드 닫기·복귀, 비활성화 후 콜백 무효화, 개인정보 양식 실패 후 수동 재개를 검증했다.
- SDK 모형 검사에서 초기 동의 콜백 처리기가 없으면 초기화가 멈추는 문제를 재현해 수정했다. 실제 SDK를 사용하는 PlayMode 테스트로 동의 갱신부터 테스트 광고 로딩까지 확인한다. 광고 대역만으로 SDK 시작 성공을 판단하지 않는다.
- 320×568에서 결과의 광고 예고·세 버튼이 겹치지 않는 것을 캡처로 확인했다. Google의 SDK 모형 전면 광고 표시와 실제 모형 닫기 버튼을 통한 새 판 진입을 확인했다. 이 검사는 Android·iOS의 네이티브 광고 검증과 별개다.
- 실제 프리팹에 광고 예고와 개인정보 설정 버튼을 연결하고 Android 앱 ID를 SDK 설정 에셋에서 확인했다. 자동 흐름 테스트에는 광고 대역을 사용한다.
- Unity CLI/Pipeline의 작업 실행으로 **Android IL2CPP 개발 빌드 성공**. `Builds/Android/Squapple-development.apk`, 88,110,154바이트. 생성된 광고 플러그인 Android manifest에서 전달받은 앱 ID를 확인했다. SDK 초기화 수정 후 다시 만든 APK다. 빌드의 임시 앱 식별자·미리 로드할 에셋 설정은 작업 전 값으로 복원했다.
- 실제 휴대폰에서의 네이티브 광고·UMP 표시·앱 전환은 별도 확인 항목이다. 실기기 광고 기회는 일반 판 5회·실제 플레이 600초 동시 충족 이후의 결과에서 발생한다. 빠르게 끝나는 판 5개만으로는 600초를 채우지 않는다.
- QA에 사용한 로컬 기록·광고 빈도 데이터를 복원하고 테스트용 화면 크기·캡처 에셋을 정리했다. 게임 씬이 변경되지 않았음을 확인했다. EDM4U의 생성 캐시·로컬 에디터 환경 파일은 버전 관리에서 제외한다.

출시 전에 Android·iOS 각각에서 테스트 광고 표시와 닫기, 오프라인, 동의 거부·변경, 외부 광고 앱에서 복귀, 강제 종료 이후 빈도·기록 유지, 화면 회전·Safe Area를 확인한다. iOS 운영 ID·최종 추적 설정과 양쪽 스토어 개인정보 표시는 아직 완료되지 않았다.
