# 중단·복귀와 화면/라운드 수명

- 작업일: 2026-10-09
- 대상: 5단계, 기본 솔로 플레이 화면
- 기준: 앱 전환·잠금·포커스 상실 때 정지하고, 돌아온 뒤 사용자가 직접 재개한다. 진행 중 판은 프로세스 종료 후 복원하지 않는다.

## 동작

앱 중단 또는 포커스 상실 알림을 받으면 세션을 정지하고 진행 중 드래그, 효과음, 임시 점수 안내를 취소한다. 홈에서 설정의 효과음을 확인 중인 경우에도 소리를 멈춘다. 확정된 점수와 제거된 사과는 그대로 둔다.

`OnApplicationPause`와 `OnApplicationFocus`는 별도로 기억한다. 중단 해제와 포커스 복귀가 모두 확인되기 전에는 새 판·재개·선택·효과음 요청을 받지 않는다. 어느 복귀 알림에서도 자동으로 재개하지 않는다. 설정이나 새 판/나가기 확인창이 열려 있으면 먼저 닫아야 ‘계속’으로 돌아갈 수 있다.

화면 또는 화면 제어기를 비활성화할 때도 같은 정지 처리를 한다. 다시 활성화해도 일시정지를 유지한다. 세션의 시간 계산은 정지 전까지의 경과 시간만 누적하므로 중단 중 실제 시간이 흘러도 남은 시간이 줄지 않는다. 정지 요청 시 이미 제한 시간이 끝났다면 기존 규칙대로 시간 종료를 우선한다.

Unity는 초기화 때 `OnApplicationPause(false)`도 전달한다. Android에서는 키보드·홈 전환 상황에 따라 포커스 알림 대신 중단 알림이 전달될 수 있으므로 두 알림을 한 값으로 덮어쓰지 않는다. [Unity 중단 콜백](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/MonoBehaviour.OnApplicationPause.html), [포커스 콜백](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/MonoBehaviour.OnApplicationFocus.html).

## 수명과 정리 책임

| 범위 | 생성 | 정리 |
| --- | --- | --- |
| 플레이 화면 | 프리팹의 `Awake`: 보드 셀, 버튼 연결, 보드 입력 이벤트 | 비활성화 시 정지·선택/소리 취소. 파괴 시 입력 이벤트 해제 및 세션 정리 |
| 한 판 | 새 판마다 `GameSession`과 상태 구독 하나 생성 | 새 판·홈·화면 파괴 때 상태 구독을 먼저 해제하고 세션을 폐기 |
| 임시 연출 | 선택 결과 안내, 제거 칸 색 표시, 효과음 | 중단 시 취소. 다음 판에서 이전 안내를 비움. 취소가 게임 데이터에 쓰기 작업을 하지 않음 |
| 앱 | 저장된 소리·진동 설정을 읽음 | 진행 중 판은 메모리에만 존재. 다시 실행하면 홈에서 시작 |

현재 판에 UniTask·트윈·외부 비동기 콜백은 없다. 폐기한 세션은 `Tick`·선택 요청을 거절하며 새 판의 화면 구독과 연결되지 않는다. 광고 SDK의 닫기·실패·외부 앱 복귀는 7단계에서 실제 콜백을 연결한 뒤 검증한다.

## 검증 범위

Unity CLI/Pipeline으로 실제 `PlayPrototype.prefab`을 사용하는 PlayMode 테스트를 실행한다. 중단·포커스 알림은 직접 전달하므로 OS가 실제로 알림을 보내는 과정까지 검증한 것은 아니다. 테스트는 임시 효과음 설정과 난수 상태를 원래대로 복원한다.

PlayMode **9/9 통과**. 수정 전 테스트 8개 중 6개가 실패했고 수정 후 통과했다. 화면/앱 중단 10회 반복 검사를 추가한 최종 실행도 모두 통과했다. 테스트는 `Assets/Tests/PlayMode/PlayLifecycleTests.cs`에 있다.

기존 규칙·세션·입력 EditMode **75/75 통과**, Unity 컴파일 오류 0개. 이번에는 모바일 빌드·설치나 실제 기기의 OS 전환을 수행하지 않았다.

열린 에디터에서 `unity command run_tests --mode playmode --filter Squapple --filter_type testName --async_tests`로 실행하고 `unity command test_status`의 `completed`와 통과 수를 확인한다. 실행 직후 반환되는 0개/`running`은 완료 결과가 아니다.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 드래그 도중 중단 | 선택 취소, 시간 정지, 복귀 후 직접 재개, 이전 손가락 놓기 무효 |
| 두 복귀 알림의 순서 교환 | 하나만 복귀한 동안 새 판·재개 차단 |
| 홈 설정에서 효과음 확인 중 전환 | 소리 정지, 중단 중 효과음 재생 차단, 설정창 유지 |
| 설정·확인창과 수동 정지/앱 중단 겹침 | 자동 재개 없음, 열린 확인창을 우회해 재개하지 않음 |
| 화면 제어기 비활성화 | 시간·소리 정지, 다시 켜도 직접 재개 필요 |
| 빠른 새 판 30회 | 이전 세션 폐기, 점수 혼입 없음, 보드 셀 중복 생성 없음 |
| 화면 비활성화·앱 전환 10회 | 세션 유지, 중단 시간 제외, 매번 재개 가능 |
| 성공 선택 후 중단·화면 파괴/재생성 | 확정 점수·보드 보존, 파괴 후에는 새 홈과 빈 세션 |

## 다음 실기기 점검

사용자가 Mi Mix 2s에서 화면 크기와 새 빌드의 기본 동작을 확인했다. 아래 항목은 이번 자동 테스트와 별도로 새 빌드에서 확인할 항목이다.

- 드래그하는 중 홈으로 이동하고 돌아오기: 선택이 사라지고 정지 화면이 보이는지 확인한다.
- 화면을 잠갔다 10초 뒤 해제하기: ‘계속’ 전에는 남은 시간이 줄지 않는지 확인한다.
- 설정에서 효과음을 확인하면서 앱 전환하기: 복귀 후 설정창은 유지되고 소리가 다시 시작되지 않는지 확인한다.
- 수동 정지·설정·새 판 확인창 각각에서 앱 전환을 반복하기: 자동 재개나 입력 잠김이 없는지 확인한다.
- 앱을 강제 종료한 뒤 다시 실행하기: 홈으로 시작하고 소리·진동 설정이 유지되는지 확인한다. 기록 유지 확인은 6단계 저장 구현 후 추가한다.
- Android와 iOS 모두에서 실제 콜백 전달과 복귀를 확인한다. 노치·홈 바 기기의 화면 확인도 남아 있다.
